# Birdora 鸟类图鉴第二阶段说明

更新日期：2026-06-29

## 1. 当前目标

第二阶段先解决“识别结果能被用户查到和看懂”的产品骨架，不直接承诺已经补齐 1000+ 种百科资料。

当前已完成：

- 使用 `assets/osea/bird_info.json` 生成 10,964 个基础图鉴索引。
- 建立 `assets/atlas/common-bird-candidates.json`，作为 100 种常见鸟富资料补齐队列。
- 图鉴搜索支持中文名、英文名和拉丁名。
- 默认优先展示已补充图文资料的 11 种常见鸟，并展示部分 OSEA 基础标签。
- 识别 Top 5 候选可点击跳到对应图鉴详情。
- 未补资料的鸟种显示“基础标签 / 图片待补充 / 资料待补充”，避免误导。

## 2. 数据分层

当前图鉴数据分两层：

1. 富资料层：`assets/atlas/bird-profiles.json`。
   - 有中文名、拉丁名、栖息地、特征、食物、观察线索、图片和来源。
   - 当前 11 种。

2. 基础标签层：`assets/osea/bird_info.json`。
   - 有中文名、英文名、拉丁名。
   - 当前 10,964 条。
   - 没有图片、栖息地、食性、分布、相似鸟和版权信息。

页面会从富资料里的 `oseaIndex` 自动生成 OSEA index 到本地富资料鸟种的关联。

新增或修改富资料后运行：

```bash
pnpm test:atlas
```

校验脚本会检查必填字段、重复名称、重复拉丁名、重复 OSEA index，以及 OSEA 标签中的拉丁名是否一致。
部署脚本会在同步 `public/` 前运行 `pnpm test:atlas`，防止半成品富资料进入上线目录。

从候选清单生成富资料模板：

```bash
pnpm atlas:template 11
```

输出的模板需要补齐真实栖息地、形态特征、食性、图片、来源、署名和许可证后，才能放进 `bird-profiles.json`。

如果 `assets/atlas/bird-profiles.json` 加载失败，页面会回退到 `script.js` 里的 10 种内置兜底资料，并在图鉴摘要里提示。上线验收时不能只看页面有鸟卡片，必须确认浏览器网络请求中 `assets/atlas/bird-profiles.json` 返回 `200`。

## 3. 版权边界

第二阶段不要批量抓取外部图片直接上线。

后续补图片时必须记录：

- 图片 URL
- 作者或机构
- 许可证
- 来源页面
- 是否允许商用和改作
- 是否需要署名

没有确认授权的图片只能显示“图片待补充”。

当前页面会展示 `imageCredit` 和 `license` 字段。若后续资料条目没有图片，页面会自动使用“图片待补充”占位图。

本地静态服务对 JSON 数据文件使用 `no-cache`，避免图鉴资料更新后仍读取旧缓存。
生产 Nginx 配置也已对 `.json` 设置 `Cache-Control: no-cache`。

## 4. 下一步资料补齐顺序

建议优先补：

1. 常见城市和湿地鸟类 100 种。
2. 中国常见候鸟和留鸟 300 种。
3. OSEA 识别高频候选的相似鸟对比。
4. 再扩展到 1000+ 种基础资料。

每个鸟种建议补齐：

- 中文名
- 英文名
- 拉丁名
- 主要栖息地
- 形态识别点
- 食性
- 分布区域
- 相似鸟
- 观察建议
- 图片和版权来源
